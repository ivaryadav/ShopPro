# routes/tenants/

**Historical note (corrected during the RC1 repository audit)**: this README originally described a Phase 3 that never happened as planned here. The actual Phase 3 (`docs/architecture/Phase3Review.md`) was Operations Domain *architecture* only (no code), and ADR-0008 decided the Operations domain would be normalized (Hybrid Storage Strategy) — but the resulting Phase 4 implementation put each entity under its own dedicated route folder (`routes/inventory/`, `routes/customers/`, `routes/sales/`, `routes/repairs/`, `routes/expenses/`, `routes/settings/`), not here. This folder remains empty and reserved for genuine tenant-status-administration endpoints (as opposed to per-entity business data), which no phase has ported to `server/src/` yet.

Still relevant: whichever future phase does port tenant-status administration must not reintroduce the two-unsynchronized-status-representations bug fixed in `docs/independent-audit/APIAudit.md` / `FinalBlockerResolution.md` — this is the layer where "one source of truth" for tenant activity status would be enforced.
